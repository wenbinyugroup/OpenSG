01 Install OpenSG#

OpenSG runs on Linux x86-64. It needs conda (Miniconda or Miniforge). No GPU is needed.

Install#

These are the four commands of OpenSG's README:

git clone https://github.com/wenbinyugroup/OpenSG.git
cd OpenSG
conda env create -f environment.yml
conda activate opensg

environment.yml installs the scientific stack from conda-forge and the JAX stack with pip. It then installs the repository itself in editable mode. That puts three commands on your PATH:

command

what it runs

opensg

the one command for every SG: it reads the msg: key of the yaml and hands the file to its engine

opensg_solid

the engine for SGs of solid elements

opensg_shell

the engine for SGs of shell elements

The environment installs the CUDA 12 build of JAX. That build also runs on a machine without a GPU. The environment is large. On one Linux machine it took about 12 GB on disk, and its packages were about 5.7 GB to download. conda env create took about 5 minutes there, with part of the conda packages already in conda's cache.

For a machine without a GPU, the repository also has environment-cpu.yml. It installs the CPU builds of JAX and PETSc and leaves out the CUDA packages. On the same machine it took about 4.4 GB on disk, and its packages were about 1.1 GB to download. To use it, run conda env create -f environment-cpu.yml in place of the third command. It makes an environment of the same name, opensg, so the fourth command stays the same. OpenSG's installation page describes another CPU-only route, an edit of environment.yml, and a plain pip install.

Check the command#

opensg --help

It prints the OpenSG banner, the usage of every command and the solver menu. The first lines are:

 ============================================================================
 OpenSG -- a multiscale structural analysis tool based on the Mechanics of
 Structure Genome (MSG), developed by the Multiscale Structural Mechanics
 Group led by Prof. Wenbin Yu at Purdue University
 ============================================================================

opensg command line -- ONE command for both MSG engines:

    opensg <sg.yaml>        homogenization (the default)
    opensg <sg.yaml> D      dehomogenization: homogenize, then recover.

A first run#

Run the plate example of the repository. Start in the root of the repository, the OpenSG folder of the clone:

cd examples/OpenSG-solid/3_get_plate_props_from_2D_SG
opensg RHC_SW_2UC_45.yaml
cd ../../..

It writes RHC_SW_2UC_45.out, the plate law, and RHC_SW_2UC_45_mesh.png, a picture of the mesh. The plate tutorial reads both files. The last line goes back to the root of the repository. Every tutorial starts there.

How long a run takes depends on the environment, the machine, its load and the number of threads. Each thread count below is the value given to OMP_NUM_THREADS, MKL_NUM_THREADS and OPENBLAS_NUM_THREADS. On one Linux machine, in the environment of the README, this run printed Time taken: 3.89 sec with 1 thread, Time taken: 22.89 sec with 4 threads and Time taken: 70.11 sec with 8 threads. The 3-D solid of tutorial 06 printed Time taken: 71.67 sec with 1 thread and Time taken: 432.75 sec with 4 threads. In this environment 1 thread was the fastest. To set it before the tutorials:

export OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1

Every run writes its files next to the yaml. It replaces the files of the same name that ship in the example folder, here RHC_SW_2UC_45.out. The plate dehomogenization run also adds two lines to RHC_SW_2UC_45.ff. git checkout -- examples, run in the root of the repository, brings back the files that ship.

One command, one yaml#

Every tutorial on this site uses the same pattern. OpenSG's README sums it up:

opensg <sg.yaml>            homogenization (the default)
opensg <sg.yaml> D          dehomogenization: homogenize, then recover the local fields
opensg <sg.yaml> --center   shell SG only: the contour is the laminate mid-surface instead of the outer mold line
opensg <sg.yaml> --mesh     also draw <base>_mesh.png
opensg --help               every flag, the solver menu and the conversion sub-commands

The yaml says what to compute. The next page shows what it holds.
